# iOS 同期のトラブルシューティング

本番は `https://running-readme-api.amtt.workers.dev` です。次の手順では、認証トークンを公開 URL、通知、スクリーンショット、チャットへ表示しないでください。

## ランニングが取得できない、合計が 0 になる

1. iPhone のロックを解除してください。
2. Mi Fitness の同期後、ヘルスケアに対象のワークアウトがあることを確認してください。
3. Actions **Find Workout** の **Workout Type** が **Running** であることを確認してください。**Stair Climbing** のままにしないでください。
4. 取得数の **Limit** が表示される場合はオフにしてください。
5. ヘルスケアのプロフィールからアプリのアクセス一覧を開き、Actions のワークアウト読み取り権限を確認してください。画面名は iOS バージョンによって異なります。Actions を手動実行した際の権限要求も確認してください。
6. 選択した記録元が、実データの **Source Bundle Identifier** または **Source Name** と一致することを端末内で確認してください。表示名を推測しないでください。
7. `YearStart` と `Now` が文字列ではなく日付型で、開始年が日本時間の現在年であることを確認してください。

Apple の設計上、HealthKit の読み取り拒否は「読めるデータがない」と区別できません。利用できる履歴の範囲が制限される場合もあります。0 件の自動送信は停止させてください。本当にゼロの年は、[手動確認後のゼロ送信](ios-shortcuts.md#9-本当に-0-件の年を送信する)を使います。

## 距離が 1,000 倍、時間が 60 倍ずれる

1. 送信を止め、既知の実際のワークアウト 1 件だけで変換結果を確認してください。
2. **Total Distance** を「測定単位を変換」でメートルにしてください。
3. **Duration** を「測定単位を変換」で秒にしてください。
4. 各結果から取り出した数値が 1 個であることを確認してください。例えば実際の 5 km・30 分なら `5000` と `1800` です。これは変換確認の例で、本番送信するダミーデータではありません。
5. JSON の各値を Number にしてください。`"5 km"`、`"30 min"`、`"01:30:00"` のような文字列は送れません。
6. 変換を修正後、年間全体を再同期してください。同じ年の値は上書きされます。

**Duration** は時間の測定値です。既定の表示単位を秒と仮定してはいけません。**End Date − Start Date** は一時停止時間を含む可能性があるため、代用しないでください。

## Total Distance がない

Actions の **Total Distance** は省略可能なプロパティです。対象項目が存在しても、距離がないことがあります。ショートカット全体を停止し、Mi Fitness からの同期内容を端末内で確認してください。欠損をゼロに置き換えたり、その項目だけ黙って除外したりしないでください。部分的な年間合計を公開する原因になります。

## 合計が二重になっている

1. 対象ワークアウトの記録元を端末内で確認してください。
2. 年間集計を、確認した 1 つの **Source Bundle Identifier** または **Source Name** に限定してください。
3. **Identifier** が同じ項目は `SeenIds` で 1 回だけ集計してください。
4. 同じ記録元で、別の Identifier を持つ同一運動がある場合は、ヘルスケアの元記録を確認してください。

別の Identifier を持つ記録が同じ運動かどうかを、このサービスは自動判定しません。時刻だけで除外すると、正当な別の運動を失う可能性があるためです。元データの削除・変更はこのサービスでは行いません。[Apple のデータソース優先順位](https://support.apple.com/ja-jp/108779)は表示上の整理についての説明です。Actions のワークアウト取得が自動で重複排除される根拠にはなりません。

## HTTP 401 UNAUTHORIZED

1. **Keychain: Get** の **Key** が `running-readme.ingest-token` であることを確認してください。
2. [Keychain の初回設定](ios-shortcuts.md#1-トークンを一度だけ-keychain-に保存する)を再実行してください。
3. 標準 **Get Contents of URL** のヘッダは `Authorization`、値は `Bearer`、半角スペース、Token 変数の順にしてください。
4. Extended アクションの **Bearer Token** 欄を使う場合は、トークン変数だけを指定してください。この欄に `Bearer ` を重ねて付けないでください。
5. 入力時の改行や前後の空白を取り除いてください。サーバー側 Secret を変更した場合は、iPhone 側も入れ直してください。

トークンの中身を表示してデバッグしないでください。誤って公開した場合は、Mac で新しいトークンを生成して Workers Secret を置き換え、iPhone の Keychain を更新する必要があります。公開済みの値を削除するだけでは失効しません。

## HTTP 400、413、415、503

| 応答 | 確認すること |
| --- | --- |
| `400 INVALID_JSON` | 本文が正しい JSON か確認してください。JSON 全体を引用した文字列として送らないでください。 |
| `400 INVALID_STATS` | キーは `year`、`distanceMeters`、`durationSeconds` だけです。すべて有限の非負数で、年は 1970 以上、日本時間の現在年以下の整数です。距離上限は 100,000,000 m、時間上限はその年の総秒数です。 |
| `413 PAYLOAD_TOO_LARGE` | 本文は 1024 バイト以下です。ワークアウト一覧や追加プロパティを送らないでください。 |
| `415 UNSUPPORTED_MEDIA_TYPE` | `Content-Type` を `application/json` にしてください。 |
| `503 SERVICE_UNAVAILABLE` | 通信を再試行し、`/health` を確認してください。設定の問題が続く場合は Mac 側で Secret と KV Binding を確認してください。 |

4xx のエラーには `ok: true` がありません。エラー本文が返ってきたことを送信成功と扱わないでください。

## 22:00 に動かない、ロック中だけ失敗する

1. オートメーションが有効で、「時刻」「毎日」「22:00」になっていることを確認してください。
2. 確認なしの実行設定を確認してください。Apple の iOS 26 ガイドでは「実行の前に尋ねる」をオフにし、「尋ねない」で確定します。「すぐに実行」が表示されるビルドではそちらを選択してください。
3. iPhone のタイムゾーンを確認してください。この手順のスケジュールは、日本時間の端末時計を前提にしています。
4. ロックを解除し、同じショートカットを手動実行してください。
5. 初回の Health 権限やネットワーク許可が残っていないか確認してください。
6. Actions が取り除かれている場合は再ダウンロードし、手動実行を確認してください。

時刻トリガーの自動実行と、Health データの読み取り可否は別の条件です。[Apple の Health データ保護](https://support.apple.com/en-au/guide/security/sec88be9900f/web)により、ロック状態では読み取れない場合があります。バックグラウンド完了や定刻成功は保証しません。ロック解除中に数分後の時刻で試験し、その後に普段のロック状態でも別途確認してください。

失敗時の無限待機や自動再試行はありません。ロック解除後に年間全体を再送してください。保存後に通信応答だけが失われた場合も、上書きなので再送で二重加算されません。

## API が未登録、または古い値を返す

1. [稼働確認](https://running-readme-api.amtt.workers.dev/health) が `{"status":"ok"}` を返すことを確認してください。この応答だけではデータ保存を証明しません。
2. 同期ショートカットの `ok` と返却された 3 項目の一致を確認してください。
3. [現在年の JSON](https://running-readme-api.amtt.workers.dev/v1/stats) を確認してください。日本時間の現在年が対象です。必要なら `?year=2026` のように対象年を明示してください。
4. 保存直後なら 60 秒以上待って再確認し、必要に応じて数分後も確認してください。KV は結果整合性であり、60 秒以内の反映を保証しません。

未登録の JSON は HTTP 404 と `STATS_NOT_FOUND` です。これは 0 km の登録とは違います。HTTP 200 で `distanceKm: 0` と `durationSeconds: 0` なら、ゼロの年間合計が登録されています。

## SVG は新しいのに GitHub README が古い

1. [ライト SVG](https://running-readme-api.amtt.workers.dev/running.svg?theme=light) と[ダーク SVG](https://running-readme-api.amtt.workers.dev/running.svg?theme=dark)を直接開いてください。
2. JSON が新しく SVG も新しい場合は、GitHub 側の画像プロキシ・キャッシュを確認してください。
3. 時間を置いて README を開き直してください。GitHub 側の更新期限は保証できません。
4. 手動で再取得を促す必要がある場合は、GitHub の公式案内に従って該当する Camo URL のキャッシュを消去してください。[GitHub の Camo トラブルシューティング](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-anonymized-urls)をご参照ください。

Worker は SVG に `no-cache, max-age=0, must-revalidate` を返します。このヘッダだけで、GitHub のキャッシュが直ちに更新されるとは保証できません。URL に未対応のクエリを足す方法は使わないでください。この API は不明なプロパティを拒否します。日々の README コミットも不要です。

## Actions が一覧に出てこない

[Actions 開発元の案内](https://sindresorhus.com/actions#faq)では、OS 側の問題として再起動などを説明しています。まず iPhone を再起動して確認してください。再インストールするときは、端末内 Keychain の保存値を再設定する準備もしてください。再インストール時に今回の値が保持されるかは未検証です。

この文書で未検証なのは、利用者様の iPhone 上の操作、単位変換、Keychain の実行、Health 集計、自動化です。サーバーの検証結果とは区別してください。
