# 今のメモ用テキストをAPIへ送る

この方法では、iPhoneはRunningの記録をテキストにして送るだけです。APIが日本時間の対象年を選び、年間合計とその年の直近5件を作ります。`YearStart`・`Now`の辞書取得や日付変換、iPhoneでの距離・時間の合計は不要です。

本番の送信先は `https://running-readme-api.amtt.workers.dev/v1/workouts` です。元データは変更しません。送信するのはメモ全体ではなく、今回の実行で作ったワークアウトのテキストです。

実機の画面全体は操作していません。利用者様のスクリーンショットとメモ出力を根拠にした手順です。サーバーのパーサ・保存・公開処理は自動テストで検証しますが、iPhoneでの初回送信は利用者様の確認が必要です。

## 1. 既存ショートカットを複製する

現在メモを保存できているショートカットを複製してください。複製を `Upload Running README` とします。元のメモ用ショートカットは残して構いません。

複製した側で次を変更してください。以前追加した `Tokyo` のテキスト、年を計算するJavaScript、`YearStart`・`Now`を作る辞書・日付の処理は今回不要です。これらを外し、Workout検索から始められます。

1. **Workoutを検索** の **制限** をオフにします。「15項目」のままでは年間全件の集計になりません。
2. **フィルタを追加** で **Workout Type = Running** にします。Walking・Cycling・Stair Climbingを含めるOR条件は、今回のアップロードでは不要です。
3. **Workoutsから選択** を外します。これは実行時に記録を選ぶ操作なので、全件の自動送信には使いません。
4. **各項目を繰り返す** を追加します。入力は **Workoutを検索** の **Workouts** です。
5. 各記録を表示していた **テキスト** を、繰り返しの内側へ置きます。
6. テキスト内の各変数を、選択した項目ではなく **繰り返し項目** のプロパティへ差し替えます。変数をタップして、元のWorkoutとプロパティを確認してください。

別アプリも同じ運動をHealthに登録している場合は、繰り返し内で確認済みの **Source Bundle Identifier** または **Source Name** に限定してください。識別子は実データで確認し、推測で入力しません。APIは見かけが異なる別記録を同じ運動だと判断できません。

## 2. テキストを4行にする

各項目のテキストは次の形にします。角括弧部分には文字列を直接書かず、**繰り返し項目** の該当プロパティをマジック変数として入れてください。

```text
Workout Type: [Workout Type]
Date: [開始日 / Start Date]
Duration: [継続時間 / Duration]
Distance: [Total Distance]
```

現在のメモにある日付表示 `yyyy/MM/dd HH:mm` と、秒・m付きの出力をそのまま使えます。日付は **日本時間** としてAPIが解釈します。端末が日本時間で出力していることを確認してください。旅行中などに別タイムゾーンで出力すると、日付と集計年がずれる可能性があります。

- 距離は `2,500 m` または `2.5 km` のような単位付き数値です。
- 時間は `900秒` または `900秒 (15 min : 00 sec)` のような出力です。括弧内は集計に使いません。
- カンマ区切りは3桁ごと、小数点は `.` で、小数は6桁まで対応します。別形式は推測で解釈せずエラーにします。
- 必要なら `Identifier: [Identifier]` を5行目に追加できます。同じIDで開始日時・距離・時間が異なる場合は送信全体を拒否します。同じ内容の重複は1件として集計します。
- **End date、Heart rate、Active calories、Avg Speedはテキストから外してください。** 旧形式として送られてもAPIは保存・公開しませんが、送信自体を減らすためです。
- 距離や時間が欠損している記録をゼロへ置き換えないでください。APIは欠損を拒否します。

このテキストを繰り返し内の最後の出力にしてください。コピー側の「メモに追加」は外し、繰り返し結果がNoteオブジェクトではなく、このテキストになるようにします。

## 3. 全件のテキストをまとめる

1. 「繰り返しの終了」の後に **テキストを結合** を追加してください。
2. 入力に **繰り返しの結果** を指定してください。
3. 区切りは **改行** にしてください。空行を区切りにしても受け付けます。
4. 必要なら結合結果を変数 `WorkoutsText` と名付けてください。

出力は、`Workout Type:` で始まるブロックが記録数だけ並んだテキストです。JSONを手入力して改行を `\n` に置換する必要はありません。後述のJSON本文アクションが文字列をJSONにします。

最初はクイックルックで結合結果を端末内だけで確認してください。手動選択の1件だけでなく、Runningの全記録が並んでいることを確認します。対象年のRunningが0件の場合、APIは既存値をゼロで上書きせず停止します。本当にゼロの年だけ、旧集計APIで手動確認して登録します。

## 4. 本文はテキスト1項目だけ

トークンは既存のActions Keychainにある `running-readme.ingest-token` を使います。まだ保存していない場合は[トークン初期設定](ios-shortcuts.md#1-トークンを一度だけ-keychain-に保存する)を参照してください。

1. **Keychain: Get** を追加します。Keyは `running-readme.ingest-token` です。
2. 続けて **URLの内容を取得** を追加します。
3. URLを `https://running-readme-api.amtt.workers.dev/v1/workouts` にします。
4. **方法 / Method** を **POST** にします。
5. **ヘッダ / Headers** を次のように設定します。

   | キー | 値 |
   | --- | --- |
   | `Authorization` | 固定文字の `Bearer ` と、Keychainの出力変数 |
   | `Content-Type` | `application/json` |

6. **本文 / Request Body** を **JSON** にします。
7. 項目を1つ追加します。キーは `workoutsText`、種類は **テキスト / Text** です。
8. 値には、上の **テキストを結合** の結果をマジック変数で指定します。Keychainのトークンを本文へ入れないでください。

本文の形式は以下です。これは説明用です。実際はJSON欄にテキスト変数を指定してください。

```json
{
  "workoutsText": "Workout Type: Running\nDate: 2026/01/15 07:30\nDuration: 900秒\nDistance: 2,500 m"
}
```

上の例は架空データです。本番にそのまま送信しないでください。通常は `year` を追加する必要はありません。APIが日本時間の現在年を選びます。過去年を再集計する場合だけ、JSONにNumber型の `year` を追加してください。

## 5. 初回同期と成功確認

1. ロック解除中に、Healthの同期とActionsの読み取り許可を確認します。
2. 自動化前に手動で実行します。
3. 返るJSONで `ok` が真、`year` が対象年、`workoutCount` がその年のRunning件数と一致することを確認します。
4. `distanceMeters` と `durationSeconds` をHealthの対象年の記録と照合します。`ok: true` は送信した範囲の処理成功であり、全件取得できたことの証明ではありません。
5. [年間JSON](https://running-readme-api.amtt.workers.dev/v1/stats)と[直近5件JSON](https://running-readme-api.amtt.workers.dev/v1/workouts)を開きます。
6. [SVG](https://running-readme-api.amtt.workers.dev/running.svg)と[プロフィール](https://github.com/nematatu)で、年間合計とその年の直近最大5件を確認します。

公開される個別情報は **日付・距離・所要時間** です。開始時刻、Identifier、元テキスト、心拍数などは保存・公開しません。全記録はリクエスト中だけ処理し、KVには年間合計と直近最大5件だけを保存します。

## 6. 毎日22:00に動かす

手動同期後、既存の時刻オートメーションの実行先を `Upload Running README` にします。毎日22:00、確認なしの実行設定にしてください。端末時計は日本時間を前提にします。

ロック中のHealthアクセスやバックグラウンド完了は保証しません。空結果・通信失敗時は成功扱いにせず、ロック解除後に再実行します。同じ全件テキストの再送は上書きであり、二重加算されません。

## エラー時

- `INVALID_WORKOUT_TEXT`: ラベル、日付、単位、欠損、重複キー、未知の行を確認します。入力を推測して保存しません。
- `NO_RUNNING_DATA`: 対象年のRunningがありません。権限・フィルタ・全件取得を確認します。既存値は保持されます。
- 同じ開始日時・距離・所要時間の記録は、単位の違いを正規化して1件として集計します。Identifierが異なっていても同じ扱いです。正当な別記録がこの3項目すべてで一致する場合も1件にまとめられるため、初回に件数を照合してください。
- `DUPLICATE_WORKOUT`: 同じIdentifierに異なる開始日時・距離・所要時間が含まれています。既存データは変更されません。端末内で該当記録と送信元を確認してください。異なる値の重複記録は自動判定できません。
- `PAYLOAD_TOO_LARGE`: 本文上限は1MiBです。15件へ制限して送ると年間値が不完全になるため、上限回避として部分送信しないでください。

KVの結果整合性とGitHub Camoにより、保存後の表示には遅延があります。60秒以上待って直接JSON・SVGを確認してください。反映期限は保証しません。
